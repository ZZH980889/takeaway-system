# 实验三：食间外卖系统

Python + Flask + SQLite，模块化单体。前端与接口由同一服务提供。实验二保留在同级 `lab2`，实验三不覆盖其文件。

## 启动

需要 Python 3.11或更新版本（本机已用Python 3.13运行）。在本目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run.py --seed --port 5001
```

若当前Python已有依赖，也可直接运行 `python run.py --seed --port 5001`。打开 <http://127.0.0.1:5001>。运行时保持终端开启，按Ctrl+C停止。不是直接双击HTML，网页依赖后端API。

`--seed`仅在空数据库时创建演示数据，不会重置已有数据。默认数据库位于 `data/takeaway.sqlite3`，签名密钥位于同目录，两者均不提交Git。可使用环境变量 `TAKEAWAY_DATABASE` 与 `TAKEAWAY_SECRET` 设置路径和密钥。

## 运行流程

1. 顾客选择菜品加入购物车；地址页可新增、修改地址。
2. 购物车按店结算，确认最新价格及地址，创建待支付订单。
3. 在订单页选择模拟支付成功或失败，成功后由商家接单。
4. 商家接单、出餐后，骑手可在大厅承接、取餐及送达。
5. 顾客确认收餐，或在送达30分钟后自动完成。
6. 配送异常由顾客或所属骑手上报，管理员决定继续或终止，填写两类退款金额。
7. 退款申请先进入“处理中”；在退款页单独模拟失败或成功。失败后可重试，终止的订单不会恢复配送。
8. 管理员还可对已付款订单发起部分退款；成功退款更新订单完成日期所属统计。

前端目前优先保证接口操作完整，采用原型样式与表格、表单、卡片组织；没有复制实验二仅存在内存中的订单数组。

## 重要规则

- 全部金额以整数分保存，接口输入价格及退款使用“元”；列表输出金额为“分”，前端转换展示。
- 所有业务修改使用立即写事务，库存条件扣减、订单快照、请求结果和日志一同提交。
- 任务名额由有效任务实时统计，待响应派单也占名额，避免额外计数器漂移。
- 幂等请求以用户及请求键唯一标识，重发返回原结果；不同参数不能复用同一键。
- 订单与菜品修改检查版本；状态不允许跳步、倒退或终止后重开。
- 付款记录成功唯一；失败支付不将订单标为付款成功。
- 退款申请先占用可退余额，处理中及失败待重试记录同样计入额度，不因重试重复申请额度。
- 未制作订单终止恢复库存，制作后不自动恢复；店铺停业或账号停用后仍允许历史任务履约。
- 地址以明确的校区字段匹配店铺配送区域，不使用真实地理围栏。
- 登录使用哈希密码和签名会话，写请求要求CSRF令牌；角色与数据归属由服务端检查。
- 日志没有修改删除API；课程结束日期未明确前不自动清理。

## 定时任务与演示加速

默认真实计时：创建5分钟未支付关闭，支付15分钟未接单取消，出餐8分钟转派单、20分钟无人承接转人工，派单60秒响应，送达30分钟自动完成。出餐时间持久化，拒绝、放弃、重新派单不重置总等待时间。

```powershell
python run.py --seed --port 5001 --time-scale 60
```

倍率60时，一分钟业务等待缩为一秒；页面明确显示倍率。默认1，不改变原始需求。验证码有效期和模拟位置10秒刷新不随业务演示倍率缩放。后台线程每秒扫描；手动扫描入口仅限管理员。重启后根据持久化时刻恢复检查。

自动触发退款只创建独立申请，不直接宣布退款成功；需管理员在退款模拟器执行结果，这样可以演示失败与重试。

## 测试和风格

```powershell
python -m pytest -q --junitxml=verification/tests.xml
python -m ruff check backend run.py tests tools
python -m ruff format --check backend run.py tests tools
python -m compileall -q backend run.py
python tools/benchmark.py
python tools/count_code.py
```

Ruff检查Python错误与未使用变量等规则，格式化器统一代码风格；这不等同于启用所有可选静态规则。测试使用独立临时数据库及可注入时钟，不修改运行中的演示数据。

验证覆盖完整履约、越权、CSRF、重复请求、最后库存竞争、同任务抢单、取消接单竞态、3单容量、超时边界、地址价格快照、退款失败重试、跨日统计和重启持久化。

性能基准使用1000条菜品、10000条订单、20个并发客户端，对菜品及订单各查询100次。`verification/benchmark.json`保存环境、每次耗时及统计。该基准经Flask测试客户端运行，包含权限、SQLite及JSON序列化，不包含TCP和浏览器耗时，不能表述为完整网络端到端测试。
